The resolved decisions are binding:

- Keep domain types behind `BookingServiceFacade`; it accepts `String` and `java.util.Date`.
- Load `CargoRoute` through `BookingServiceFacade.loadCargoForRouting(trackingId)` and use a per-load `new SimpleDateFormat("MM/dd/yyyy")`; do not add shared mutable formatting state or reload a domain object. Resolution 3.5 records that parsing the leading date of `cargo.getArrivalDeadline()` yields the displayed date because that string begins with `MM/dd/yyyy`. The more specific required load contract in subsection 4.3 directs this issue to parse `cargo.getArrivalDeadlineDate()`, so use that date-only accessor. Surface malformed data explicitly rather than submitting null.
- Implement a serializable CDI `@Named @ViewScoped` editor bean. The session-scoped launcher and XHTML belong to Issue 4.
- Require a non-null selection, but do not impose a minimum, future, old-deadline, or itinerary-leg chronology rule. Existing `RouteSpecification` invariants remain authoritative.
- Container-free tests should use a hand-written facade fake if practical; do not add a mocking dependency.

Research established that the DTO's displayed deadline is date-only in `MM/dd/yyyy`, while the broader formatted value starts with the same component. The editor should use the explicit date-only DTO accessor required by this task and a fresh formatter per load. Implement from production contracts, not research artifact source code.

## Implement

Create:

- `src/main/java/org/eclipse/cargotracker/interfaces/booking/web/ChangeArrivalDeadlineDate.java`

Use this required shape:

```java
@Named
@ViewScoped
public class ChangeArrivalDeadlineDate implements Serializable {
    private static final long serialVersionUID = 1L;

    private String trackingId;
    private CargoRoute cargo;
    private Date arrivalDeadlineDate;

    @Inject
    private BookingServiceFacade bookingServiceFacade;
}
```

Provide:

- `getTrackingId()` and `setTrackingId(String)`;
- `getCargo()`;
- `getArrivalDeadlineDate()` and `setArrivalDeadlineDate(Date)`;
- `load()`;
- `changeArrivalDeadline()`.

`load()` must:

1. Call `bookingServiceFacade.loadCargoForRouting(trackingId)`.
2. Store the returned `CargoRoute`.
3. Create a per-load `SimpleDateFormat("MM/dd/yyyy")`.
4. Parse `cargo.getArrivalDeadlineDate()`.
5. Store the parsed value in `arrivalDeadlineDate`.
6. Surface lookup or parse failure as a clear application/view error consistent with existing JSF handling; do not swallow it, print a stack trace, or leave a success-shaped null.

`changeArrivalDeadline()` must:

1. Reject a null selected date. The XHTML will also mark the component required in Issue 4, but this model must not silently delegate null when called directly.
2. Call `bookingServiceFacade.changeDeadline(trackingId, arrivalDeadlineDate)`.
3. Only after successful return, call `PrimeFaces.current().dialog().closeDynamic("DONE")`.
4. Leave the dialog open and surface the failure if facade delegation fails.

If practical in the current harness, add a container-free JUnit test with a hand-written fake facade proving:

- `load()` requests the exact tracking ID;
- `MM/dd/yyyy` converts to the expected editable calendar date;
- submission delegates the exact tracking ID and selected date;
- malformed DTO data is surfaced rather than converted to null;
- null submission is rejected and does not invoke the facade.

## Completion gates

- The bean is serializable and uses the repository's established CDI `@Named` and JSF `@ViewScoped` annotations.
- Its model references facade DTOs only, never `Cargo`, `TrackingId`, `RouteSpecification`, or repositories.
- Parse and null-date failures are observable and cannot look like successful updates.
- If a focused test is added, it proves the success and failure contracts without a container or new dependency.
- `.\mvnw.cmd clean package -Popenliberty` succeeds on JDK 17.
- All earlier application and facade gates remain intact.

## Out of scope

- The session-scoped launcher, dynamic-dialog XHTML, and Administration table link.
- Domain/repository access from the bean.
- A new facade DTO or changing `CargoRoute` to expose a `Date`.
- Shared `SimpleDateFormat`, new timezone policy, or new chronological validation.
- Closing the dialog after failed delegation.
- Mocking libraries, Arquillian/Payara modernization, framework migration, and unrelated web cleanup.
