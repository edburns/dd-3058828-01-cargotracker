## Implement

Modify:

- `src/main/java/org/eclipse/cargotracker/interfaces/booking/facade/BookingServiceFacade.java`
- `src/main/java/org/eclipse/cargotracker/interfaces/booking/facade/internal/DefaultBookingServiceFacade.java`

Optionally add, if it fits the existing test harness without new dependencies:

- `src/test/java/org/eclipse/cargotracker/interfaces/booking/facade/internal/DefaultBookingServiceFacadeTest.java`

Add this facade API:

```java
void changeDeadline(String trackingId, Date arrivalDeadline);
```

Implement exact one-step delegation:

```java
bookingService.changeDeadline(
        new TrackingId(trackingId),
        arrivalDeadline);
```

Keep the facade boundary narrow: presentation clients supply a string ID and `java.util.Date`; the facade converts the ID and delegates exactly once. It must not load or mutate `Cargo`, access `CargoRepository`, parse UI text, or use JSF/PrimeFaces classes.

If a focused test is practical, use a hand-written `BookingService` fake or spy to prove:

- the tracking string becomes an equivalent `TrackingId`;
- the identical `Date` object/value reaches the application service;
- delegation occurs exactly once;
- the facade performs no duplicate repository or domain mutation.

Do not distort production visibility or APIs merely to enable the optional test.
