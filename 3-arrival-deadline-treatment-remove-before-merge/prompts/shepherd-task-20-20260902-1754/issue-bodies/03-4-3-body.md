Resolved decisions: use a serializable CDI `@Named @ViewScoped` editor. Keep the web layer behind `BookingServiceFacade`; use `String` and `java.util.Date`, not domain types. Load `CargoRoute` through `loadCargoForRouting(trackingId)`, parse its `MM/dd/yyyy` date with a per-load `SimpleDateFormat`, and surface malformed data explicitly. Require a non-null selection but add no future/relative-date rule. Successful submission delegates to the facade and closes with `"DONE"`; a failed submission must not look successful.

The research finding is that container-free tests should use hand-written fakes where practical; do not add Mockito or modernize the historical Arquillian runtime.

## Implement

Create:

- `src/main/java/org/eclipse/cargotracker/interfaces/booking/web/ChangeArrivalDeadlineDate.java`

Implement a serializable CDI `@Named @ViewScoped` bean with `serialVersionUID = 1L`, fields for `String trackingId`, `CargoRoute cargo`, `Date arrivalDeadlineDate`, and an injected `BookingServiceFacade`.

Provide:

- `getTrackingId()` / `setTrackingId(String)`
- `getCargo()`
- `getArrivalDeadlineDate()` / `setArrivalDeadlineDate(Date)`
- `load()`
- `changeArrivalDeadline()`

`load()` must request the cargo through `bookingServiceFacade.loadCargoForRouting(trackingId)`, retain the returned DTO, parse `cargo.getArrivalDeadlineDate()` with a newly created `SimpleDateFormat("MM/dd/yyyy")`, and store the editable date. Do not directly query domain or persistence objects. A parsing error must become a clear application/view failure consistent with repository JSF behavior; do not print-and-continue or produce a null editor value.

`changeArrivalDeadline()` must reject a null selection, call `bookingServiceFacade.changeDeadline(trackingId, arrivalDeadlineDate)`, and only after successful return call:

```java
PrimeFaces.current().dialog().closeDynamic("DONE");
```

Add a focused container-free JUnit test if practical using a hand-written fake facade. Cover correct tracking-ID loading, date-only parsing, exact submit delegation, malformed DTO data, and null selection.

## Completion gates

- The bean is serializable and uses the established CDI/JSF annotations and repository error-handling conventions.
- It references facade types only, never domain or repository types.
- Malformed DTO dates and null selections are observable failures; neither can trigger facade mutation or successful dialog closure.
- A focused test, if feasible, discriminates `MM/dd/yyyy` conversion and prevents silent-null regression.
- On JDK 17, `./mvnw clean package -Popenliberty` succeeds and all prior task tests still compile.

## Out of scope

Do not create the launcher or XHTML, edit the dashboard, query repositories/domain objects, broaden `CargoRoute`, add shared mutable formatters, introduce a new DTO or date policy, add mocking dependencies, swallow exceptions, or close the dialog after a facade failure.
