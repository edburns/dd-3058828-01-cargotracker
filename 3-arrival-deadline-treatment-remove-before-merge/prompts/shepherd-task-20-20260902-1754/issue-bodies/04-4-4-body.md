## Implement

Create:

- `src/main/java/org/eclipse/cargotracker/interfaces/booking/web/ChangeArrivalDeadlineDateDialog.java`
- `src/main/webapp/admin/dialogs/changeArrivalDeadlineDate.xhtml`

The serializable launcher must use:

```java
@ManagedBean(name = "changeArrivalDeadlineDateDialog")
@SessionScoped
```

Implement `showDialog(String trackingId)`, `handleReturn(SelectEvent event)`, and `cancel()`. `showDialog` passes `trackingId` as `Map<String,List<String>>`, sets the exact options above, and opens the exact dialog path. `cancel()` invokes no facade work and closes with the empty string.

The XHTML title is `Change Deadline`. Put this metadata directly under root `<html>` before the head:

```xhtml
<f:metadata>
    <f:viewParam name="trackingId"
                 value="#{changeArrivalDeadlineDate.trackingId}"/>
    <f:viewAction action="#{changeArrivalDeadlineDate.load}"/>
</f:metadata>
```

Display labeled, read-only origin and destination using `cargo.originName` and `cargo.finalDestinationName`; bind a required `p:datePicker` to `arrivalDeadlineDate` with visible validation feedback; add Cancel calling the launcher and Update calling the editor. Preserve the established destination-dialog lifecycle so successful return can refresh Administration.

## Completion gates

- On JDK 17, `./mvnw clean package -Popenliberty liberty:run` starts successfully.
- Direct request to `/cargo-tracker/admin/dialogs/changeArrivalDeadlineDate.xhtml?trackingId=DEF789` returns HTTP 200, has title **Change Deadline**, renders origin/destination, and selects the current deadline.
- No `TagException`, `<f:metadata> Parent UIComponent`, `FacesException`, or server error occurs.
- Cancel leaves the persisted deadline unchanged; Update changes it and closes only after success.
- Destination editing still works.
- Liberty is stopped cleanly before completion.
